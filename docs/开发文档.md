# BizLens AI 开发文档

## 1. 产品边界

BizLens AI 的核心流程是“登录 → AI Gateway → 检索代码知识 → LLM → Output Guard → 用户”。模型可以利用代码摘要、方法元数据和调用关系回答业务问题，但对外只返回业务解释。

客户可获得：业务规则、功能说明、错误原因、操作流程、计算规则和数据解释。

客户不可获得：Java/SQL 源码、YAML/JSON 配置、内部路径、系统 Prompt、Token、Key、Secret 和数据库连接信息。

## 2. 技术栈

- 后端：Spring Boot 2.5、MyBatis、Java 8、Redis、PostgreSQL
- 前端：Vue 3、Vite、Element Plus、Pinia
- 模型：DeepSeek OpenAI-compatible API，Provider 位于 `svc/src/main/java/zzz/service/forum/ai`
- 索引模型：PostgreSQL 中保存代码元数据、摘要、JSONB embedding 和关系；后续可接入 pgvector 或独立向量数据库

## 3. 后端模块

| 模块 | 位置 | 责任 |
| --- | --- | --- |
| AI Provider | `svc/.../ai` | 组装 DeepSeek 请求，支持普通和流式响应 |
| AI 对话 | `svc/.../service/impl/AiServiceImpl.java` | 会话归属、限流、上下文、消息持久化 |
| AI 角色 | `AiAgentController` / `AiAgentService` | 系统角色和用户角色 CRUD，API Key 加密存储 |
| 安全边界 | `AiSafetyGuard` | Prompt 注入识别、源码/密钥输出拦截 |
| 认证 | `AuthController` / `AuthServiceImpl` | 注册、登录、刷新、退出和 Redis Token 校验 |
| 系统探针 | `SystemController` | 提供无需登录的 `/api/system/health`，检查应用和 PostgreSQL 连通性 |

## 4. API 约定

- `POST /api/auth/login`：登录
- `POST /api/auth/register`：注册
- `POST /api/auth/refresh`：刷新 Token
- `POST /api/auth/logout`：退出
- `POST /ai/chat/create`：创建会话
- `GET /ai/chat/conversations`：查询当前用户会话
- `GET /ai/chat/history?conversationId=`：查询历史消息
- `POST /ai/chat/send`：普通问答
- `POST /ai/chat/stream`：SSE 流式问答
- `POST /ai/chat/close`：关闭会话
- `GET/POST/DELETE /ai/agent/*`：AI 角色管理
- `GET /ai/project/list`：当前用户的代码项目
- `POST /ai/project/create`、`POST /ai/project/update`：代码项目元数据维护
- `POST /ai/project/{id}/index`：将项目状态置为 `QUEUED`，等待异步索引器处理
- `DELETE /ai/project/{id}`：删除当前用户的代码项目

`GET /ai/project/list` 会返回 `documentCount`、`chunkCount`、`symbolChunkCount`，用于确认索引产物数量；统计值由 PostgreSQL 按项目实时汇总。

所有 AI 接口要求 `Authorization` 请求头，并由认证切面校验 Redis 中的 access token。

基础状态接口 `GET /api/system/health` 不要求登录，返回 `UP` 或 `DEGRADED`，可用于容器探针和前端工作台状态卡片。

代码项目接口只允许创建者访问自己的项目。当前“排队索引”会异步执行一次安全浅克隆：只扫描限定扩展名和大小的文件，写入文档、文件级切片和轻量方法/符号级切片元数据，回写 Commit，并在完成后删除临时工作区。符号提取使用受限正则规则，不等同于完整 AST；当前仍不包含 Secret Manager、业务摘要生成和向量化能力，后续应在此基础上扩展。

## 5. PostgreSQL 数据库

建表脚本为 `svc/src/main/resources/db/schema-postgresql.sql`，使用 `CREATE TABLE IF NOT EXISTS`，可重复执行。核心表如下：

- `"User"`、`"AiAgent"`、`"AiConversation"`、`"AiChatMessage"`：在线产品基础数据
- `ai_code_project`：Git 项目、分支、Commit 和索引状态
- `ai_code_document`：文件路径、语言、符号、摘要和校验值
- `ai_code_chunk`：文件/方法级切片、业务摘要、embedding 和扩展元数据
- `ai_code_relation`：Controller/Service/Mapper/SQL/Table 等调用关系
- `ai_security_audit`：问题、检索元数据、模型、规则命中和拦截结果

源码默认不落库。索引任务应使用临时工作区拉取 Git，完成解析和 embedding 后删除源码；Git 凭据只保存 Secret Manager 引用，不保存明文密码。

## 6. 安全实现要求

1. 入库前扫描 `password`、`token`、`apiKey`、`privateKey` 等敏感内容并脱敏。
2. 通过项目权限和 AI 角色区分客户、内部员工、开发 AI 的访问级别。
3. 用户输入先经过 Prompt Injection 检测。
4. 模型输出经过 `AiSafetyGuard` 检测，命中源码、SQL、配置或密钥特征时返回统一拒答。
5. 生产环境必须设置 `DEEPSEEK_API_KEY`、`AES_KEY`、`JWT_SECRET`、数据库和 Redis 环境变量。
6. 生产环境应将审计记录写入 `ai_security_audit`，并对代码索引、模型调用和拒答事件设置告警。

## 7. 后续迭代

1. 将轻量符号提取替换为 Java AST、Mapper XML、Vue 文件的完整结构化解析。
2. 增加方法级检索、业务摘要生成和按 Git Commit 的增量更新任务。
3. 将 `ai_code_chunk.embedding` 迁移到 pgvector 或向量数据库。
4. 建立 Code Graph 检索，支持跨 Controller/Service/Mapper/Table 的调用链解释。
5. 增加项目管理接口、临时工作区任务队列和 Jenkins/Git webhook 自动同步。
