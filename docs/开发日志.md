### 澄清"没配凭据为什么能索引到私有仓库"（同日）

用户指出项目「444」（`github.com/zzzaszz/404-forum`）是私有仓库，却没有任何凭据也能索引成功。
实测澄清：

- 匿名访问 `api.github.com/repos/zzzaszz/404-forum` 返回 404 → 仓库确实是私有的。
- `GIT_TERMINAL_PROMPT=0 git ls-remote <url>` 仍成功，返回的 commit 与库里记录一致。
- 本机 `credential.helper=store`，`~/.git-credentials` 中存在 github.com 条目。

结论：克隆成功是因为 `git` 静默使用了**运行机器上存储的凭据**，而不是仓库公开。
`credential_ref` 空 ≠ 匿名访问，因此该字段不构成任何访问控制——
**任何注册用户都能借机器凭据克隆并索引自己无权访问的私有仓库**，已作为安全项记入 README 待完成第 1 项。

同时修正了两处基于错误假设的文案：列表「Git 凭据」列不再写「公开仓库可留空」。

### 切断索引克隆的环境凭据继承（同日）

按上一条结论动手修复：`AiCodeIndexServiceImpl.applyIsolatedGitEnv` 在每次索引时给 git 一套干净环境——
`HOME`/`USERPROFILE`/`XDG_CONFIG_HOME` 指向空临时目录、`GIT_CONFIG_GLOBAL` 指向不存在的文件、
`GIT_CONFIG_NOSYSTEM=1`、`GIT_CONFIG_COUNT` 把 `credential.helper` 显式置空、`GIT_TERMINAL_PROMPT=0`，
并移除 `SSH_AUTH_SOCK` / `GIT_SSH_COMMAND` / `GIT_ASKPASS`。同时改掉误导文案：
「Git 凭据」列只反映字段填没填，索引失败时明确告知"克隆已停用机器凭据、按项目凭据注入尚未实现"。

验证：

- 脱离应用直接对 `git ls-remote` 做对照：隔离环境下私有仓库报
  `could not read Username ... terminal prompts disabled`，公开仓库正常。
- 应用内：私有仓库项目 `FAILED` 且原因可读；公开仓库项目 `READY`（commit 与上游一致）。
- 副作用（预期）：项目「444」重新排队索引会失败，但其切片仍在库中，现有对话不受影响。

- **操作列 hover 变透明**：根因是表格**固定列**（`el-table-fixed-column--right`）靠自身背景遮住横向滚动过去的列，

  顺带修掉一个潜伏 bug：query 里的项目ID是**字符串**（雪花ID经 `JacksonConfig` 序列化成字符串），

### 会话删除、排版与输入框焦点环修复（同日）

- 新增 `DELETE /ai/chat/conversation/{id}`：对话页**左栏会话可右键删除**（连带全部消息，外键级联）。
  Redis 热上下文不跟着外键走，由服务层手工清理。
- **Markdown 排版修复**（用户反馈"都挤在一起"），两个原因叠加：
  1. 渲染器把模型输出里"`- **标题**` + 换行 + 说明"的**续行**当成了独立段落（CommonMark 的
     lazy continuation），说明文字掉到气泡最左边，与圆点脱节。已改为并入当前列表项。
  2. 正文样式写在 `<style scoped>` 里，而 `v-html` 渲染出的节点不带 scoped 属性，
     `.markdown-body h2` 这类选择器**一条都匹配不上**，标题/列表全用浏览器默认样式、
     再被全局 reset 抹掉内外边距。已把 Markdown 样式挪到独立的**非 scoped** 样式块，
     并整体放大排版尺度（段落 10px、列表项 8px、h2 带下划线分隔）。
- **输入框"外面多一层边框"修复**：全局焦点环规则写的是 `input:not(.el-input__inner)`，
  只挡住了 el-input；点击 el-select 时它内部的 `input.el-select__input` 被命中，
  于是在组件框外多出一圈 2px 蓝边（`[tabindex]:focus-visible` 也会命中 EP 的 wrapper）。
  已统一改为 `:not([class*="el-"])` 排除 EP 元素，并在注释里写明原因。
  实测：EP 组件保留自身主色内阴影高亮，原生控件的焦点环不受影响。
