## 4. 测试中发现并修复的问题

### 4.1 建/改角色接口把 API Key 密文原样返回（安全）

`AiAgentController` 只在 `/list` 里脱敏，`/create` 与 `/update` 返回的实体带着完整 `ApiKeyEnc`。
虽然是密文，但把库里的密钥材料交给前端不应发生（`AES_KEY` 一旦泄露即可解出明文）。
修复：抽出 `maskApiKey()`，三个出口统一走它。

### 4.2 关闭会话失败时静默返回 false

`closeConversation` 直接把 service 的布尔值返回，会话不存在或不属于自己时返回 `false` 而不报错——
前端把"失败"当成功处理。修复：与 `reopen` 对齐，归属校验不过就抛业务异常。
同时 `/close` 接口补了 try/catch（本类没有全局异常处理器，抛出去会经 `/error` 变成空 body 的 HTTP 500）。

### 4.3 两套时钟导致 `UpdatedAt` 早于 `CreatedAt`

插入会话用的是 JVM 时间（`new Date()`），而 `touch`/`updateStatus` 用的是数据库 `CURRENT_TIMESTAMP`。
本机两者相差约 13 秒，实测出现 `createdAt 11:34:10` 而 `updatedAt 11:33:57`。
会话列表正是按 `UpdatedAt` 倒序，混用两套时钟会让排序不可靠。
修复：更新时间统一由应用传入，与插入保持同一时钟。

### 4.4 流式接口未登录时返回空 body 的 HTTP 500

`AuthAspect` 在鉴权失败时返回 `R.fail(401, ...)`，但 `/ai/chat/stream` 的返回类型是 `SseEmitter`，
Spring 按方法声明类型选返回值处理器 → 类型不匹配 → 空 500，前端只能显示"发送失败：HTTP 500"，
既看不出是登录失效，也无法据此跳登录页。
修复：切面识别返回类型为 `SseEmitter` 的接口，改用带回 `event:error` 的 `SseEmitter` 返回。
前端配套：`AiChat.vue` 识别到"登录已过期"后清理本地登录态并跳登录页（流式请求走原生 fetch，不经过 axios 拦截器）。

### 4.5 续聊失败会让输入框永久禁用（本轮引入的回归）

`sendMsg` 里新增的"先重新打开再发送"写在 `try` 之外，`aiReopenConversation` 被拦截器 reject 时异常
逃出函数，`sending` 停在 `true`，输入框与发送按钮永久禁用，只能刷新页面。
修复：把续聊与发送一起纳入同一个 `try/finally`，并顺带把占位气泡下标提到 `try` 之外（否则 `catch` 里引用不到）。

### 4.6 早期会话给了"能继续"的假承诺

库里 9 条历史会话的 `AgentId` 为 `null`（会话必须绑定角色的规则是后来才加的），
它们既打不开续聊（`reopen` 会以"会话未绑定角色"拒绝），也发不出消息，
但界面提示"发送消息会自动重新打开并继续这段对话"。
修复：区分两种情况——未绑定角色的会话提示"只能查看历史"并禁用输入框；已绑定角色的才提示可续聊。

## 5.2 第三轮：澄清"没配凭据为什么能索引到私有仓库"

起因：发现项目「444」的地址是**私有仓库**，页面上却没有配任何凭据。第一轮曾判断"因为它是公开仓库"，
这个结论被实测证伪。

### 实测过程与结论

| 检查 | 命令 / 方式 | 结果 |
| --- | --- | --- |
| 仓库可见性 | 匿名 GET `api.github.com/repos/zzzaszz/404-forum` | **404 → 私有** |
| 无交互能否读到 | `GIT_TERMINAL_PROMPT=0 git ls-remote <url> HEAD` | 成功，返回 `8788cf1…`，与库里 `git_commit` 完全一致 |
| 凭据来源 | 查 `credential.helper` 与凭据文件 | 全局 `credential.helper=store`，`~/.git-credentials` 中**存在 github.com 条目** |

**结论**：克隆成功不是因为仓库公开，而是因为 `git clone` **静默使用了运行机器上存储的凭据**。
`AiCodeIndexServiceImpl.runGitClone` 确实没有传任何鉴权参数，但 `git` 会自行查找并套用
`credential.helper` / `~/.git-credentials` / SSH key / 系统凭据管理器里的凭据——
"没传参数"与"没用凭据"是两件事。

### 由此暴露的安全问题（未修复，已记入 README 待完成第 1 项）

- 项目接口只校验"项目是不是我创建的"，**不校验"我有没有权限读这个 Git 仓库"**。
  任何注册用户都可以填一个自己无权访问的私有仓库地址，让系统用机器凭据克隆并索引，
  再通过问答获取这份代码的业务信息。这与产品"不向客户泄露源码"的定位直接冲突。
- `credential_ref` 是装饰字段，事后无法审计某次克隆用的是谁的凭据。

### 顺带修正的误导文案

第一轮把该列文案改成了「公开仓库可留空」，这等于在页面上替用户断言"仓库是公开的"——
正是这次被证伪的那个假设。已改为只描述字段本身（「未填写 / 已填写（未生效）」），
并在提示里说明克隆实际用的是运行机器的凭据。

## 5.3 切断环境凭据继承（对应 5.2 的安全问题）

按 5.2 的结论做了修复，并逐条验证。

**改动**：`AiCodeIndexServiceImpl.applyIsolatedGitEnv` —— 每次索引为 git 进程准备一套干净环境：
`HOME`/`USERPROFILE`/`XDG_CONFIG_HOME` → 空的临时目录（用完随工作区一起删）、
`GIT_CONFIG_GLOBAL` → 该目录下不存在的 `.gitconfig`、`GIT_CONFIG_NOSYSTEM=1`、
`GIT_CONFIG_COUNT=1` + `credential.helper=`（空值表示重置 helper 列表）、
`GIT_TERMINAL_PROMPT=0`，并移除 `SSH_AUTH_SOCK` / `GIT_SSH_COMMAND` / `GIT_ASKPASS`。
注意是在 JVM 现有环境之上修改，**不清空环境**（`SystemRoot` 等清掉会让网络都不通）。

| 编号 | 用例 | 期望 | 实测 |
| --- | --- | --- | --- |
| S-01 | 隔离环境下访问**私有**仓库 | 失败，且报错含 `terminal prompts disabled` | 通过：`fatal: could not read Username for 'https://github.com': terminal prompts disabled` |
| S-02 | 隔离环境下访问**公开**仓库 | 成功 | 通过：`7fd1a60b…` |
| S-03 | 应用内：私有仓库项目排队索引 | `FAILED`，原因说明已停用机器凭据 | 通过（`404-forum`：`无法访问该仓库：克隆已停用运行机器的 Git 凭据…`） |
| S-04 | 应用内：公开仓库项目排队索引 | `READY` | 通过（`octocat/Hello-World`：commit `7fd1a60b01f91b314f59955a4e4d4e80d8edf11d`） |

S-01/S-02 是脱离应用、直接对 `git ls-remote` 做的对照，用来确认隔离环境本身的行为，
避免"应用里失败了"这种单一来源的结论。测试用的项目已删除。

**副作用（预期内）**：项目「444」指向私有仓库，重新排队索引会失败；
其切片仍在库中，因此现有对话不受影响。

| Y-12 | 左侧菜单顺序 | 工作台、业务问答、AI 角色、代码项目 | 通过 |
| Y-13 | 「创建角色」跳转后自动开弹窗 | 弹窗自动打开并预选该项目 | 通过 |

**发现并修复的问题**：Y-07 第一次测不通——右键菜单不出现。原因是 `openMenu` 里对没有 `id` 的消息直接返回，
而**刚发出的消息是本地追加的、没有服务端 ID**，等于"刚聊完的消息删不掉"。已加 `backfillMessageIds()`：
回复结束后按「发送方 + 内容」从服务端历史回填 ID，只补 ID 不重建列表（重建会丢掉刚算出的耗时文案）。

## 5.5 第五轮：会话删除、排版与输入框焦点环

| 编号 | 用例 | 期望 | 实测 |
| --- | --- | --- | --- |
| Z-01 | 删除会话（接口） | 返回成功，历史接口随之报「会话不存在」 | 通过 |
| Z-02 | 删除不存在的会话 | 「会话不存在或无权访问」 | 通过 |
| Z-03 | 会话消息级联删除 | `AiChatMessage` 不留孤儿行 | 通过（探针查 `残留消息行 = 0`） |
| Z-04 | 删除会话（界面） | 左栏右键出「删除整个会话」→ 确认 → 消失 | 通过 |
| Z-05 | Markdown 排版 | 列表项与说明同属一项；标题有分隔；段落有间距 | 通过（10 个列表项含续行；`ul` 22px、`li` 8px、`h2` 16px 带下划线） |
| Z-06 | 输入框焦点环不再外溢 | 点击 el-select 后其内部 input 无 outline | 通过（`outline: none`；此前是 `solid 2px` + `offset 2px`） |
| Z-07 | EP 自身焦点反馈保留 | wrapper 变为主色内阴影 | 通过（`is-focused`，`rgb(104,175,249) inset`） |
| Z-08 | 原生控件焦点环未受影响 | 仍为 `2px` 蓝环 | 通过 |

**Z-05 的两个根因**（都不是"调样式"能解决的，是渲染与作用域问题）：

1. 渲染器把「`- **标题**` → 换行 → 说明」里的续行当成了独立段落（CommonMark 的 lazy continuation），
   说明文字掉到气泡最左边，与圆点脱节。
2. Markdown 样式写在 `<style scoped>` 内，而 `v-html` 产出的节点不带 scoped 属性，
   `.markdown-body h2` 这类选择器**一条都匹配不上**——标题/列表用的是浏览器默认样式，
   又被全局 `* { margin:0; padding:0 }` 抹掉内外边距，所以"全挤在一起"。
   已把 Markdown 样式移到独立的非 scoped 样式块。

**Z-06 的根因**：全局焦点环规则是 `input:not(.el-input__inner)`，只排除了 el-input；
el-select 内部的输入框类名是 `el-select__input`，因此被命中并被画上 2px 蓝边（还有 2px offset，
看起来就是组件外面套了一层框）。`[tabindex]:focus-visible` 同样会命中 EP 组件的 wrapper。
已统一改为 `:not([class*="el-"])`。

## 6. 仍未覆盖 / 已知遗留

1. **流式对话是"尽早断"而不是"事前拦"**。打字机效果下内容会开始外送，`AiSafetyGuard`
   只能在判到的那一刻中断；已推送的部分靠 `reset` 纠正。要求"一个字符都不外泄"时应改回整段发送。
2. **索引卡死判定是启发式的 10 分钟时间窗**。真有任务跑超过 10 分钟时，界面会误放开「重新索引」，
   点了就会并发两个索引互相覆盖。根治要引入任务心跳或超时字段。
3. **索引进度不可见**：状态机只有 `PENDING/QUEUED/INDEXING/READY/FAILED`，没有中间进度上报。
4. **列表接口仍全量返回**（会话、项目、角色），未分页。
5. **按项目的 Git 凭据注入仍未实现**。环境凭据继承已切断（见 5.3），所以现在只能索引可匿名访问的仓库；
   私有仓库需要等凭据注入能力或先把仓库公开。
6. **前端无自动化测试**，本轮全部为人工驱动的端到端验证；`pnpm run test` 的 Vitest 兼容问题仍在。
7. 未验证多用户场景（越权访问他人会话/项目/角色只做了代码路径审查，未构造第二个账号实测）。
8. 未验证的接口分支：`openai` / `qwen` / `custom` 三个 Provider 的模型列表与对话（沿用 README 原有记录）。

## 7. 复现方式

```bash
# 后端构建

# 前端
cd web && pnpm install --frozen-lockfile && pnpm run dev   # http://localhost:3000

```

浏览器打开 `http://localhost:3000`，登录后按 3.5 的用例逐条走一遍即可。
