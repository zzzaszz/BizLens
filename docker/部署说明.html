2一次性准备：私有仓库与登录

2.1 在 Docker Hub 网页端新建私有仓库

  1. 登录 hub.docker.com；
  2. 进入 Create repository；
  3. Name 填 bizlens-ai，Visibility 选 Private；
  4. 创建后仓库全名为 <账号>/bizlens-ai，后面 REGISTRY 就填这个 <账号>。

免费账号可创建的私有仓库数量有限（以 Docker Hub 当前套餐为准）。若命名为别的名字，后续用 IMAGE= 传入即可。

2.2 生成 Access Token

Docker Hub 的 CLI 登录不再接受账号密码，密码位置必须填 Token：

  1. Account Settings → Personal access tokens → Generate new token；
  2. 权限选 Read & Write（只能拉取的机器可给 Read）；
  3. 生成后立即复制保存，页面关闭后不再显示。

2.3 登录（构建机与目标机都要做一次）

docker login -u <DockerHub账号>
# 提示 Password 时粘贴上一步的 Access Token，不是账号密码
# 登录成功提示：Login Succeeded

私有仓库的安全边界要说清楚：镜像内含后端 class 文件与前端产物，被授权拉取的人可以解包查看。私有仓库只保证"未授权拉不到"，不等于加密。本方案的数据库口令、Redis 口令、AES 密钥、JWT 密钥全部在运行时通过环境变量注入，不进镜像、不进仓库。

3第一步：本地打包并送到构建机

# 本地执行（Windows Git Bash 或 Linux 均可）
bash docker/package.sh

# 产物：svc/target/bizlens-ai-service-0.0.1-SNAPSHOT.jar（约 140MB）
# 该 jar 内已含：后端 + 前端静态资源 + application-prod.yml

脚本会依次：构建前端 → 把 web/dist 复制进 src/main/resources/static → mvn package → 清理临时的 static 目录。结束时打印产物路径。

构建机需要的是整个仓库加这个 jar。推荐用 git 拉仓库（脚本换行符不易出错），jar 单独传：

# 构建机上
git clone <仓库地址> /data/bizlens && cd /data/bizlens
mkdir -p svc/target

# 本地（Windows Git Bash）把 jar 传上去
scp svc/target/bizlens-ai-service-0.0.1-SNAPSHOT.jar <用户>@<构建机>:/data/bizlens/svc/target/
构建镜像需要的文件
文件来源
svc/target/bizlens-ai-service-*.jar本地打包，需手工传输（140MB，不走 git）
svc/Dockerfile随仓库
svc/entrypoint.sh随仓库
svc/.dockerignore随仓库
docker/*.sh、docker/.env.example随仓库

生产配置 svc/src/main/resources/application-prod.yml 是源码文件，已在打包时进入 jar，不需要单独传输。

若不用 git、改用 U 盘或网盘传 .sh 文件，务必确认换行符是 LF 而不是 Windows 的 CRLF——CRLF 会让容器里的 entrypoint.sh 启动失败。检查：file docker/build.sh，若输出含 CRLF line terminators，执行 sed -i 's/\r$//' docker/*.sh svc/entrypoint.sh。用 git 传输不会出现这个问题。

4第二步：构建镜像

# 构建机上，仓库根目录执行；<账号> 换成你的 Docker Hub 账号
chmod +x docker/*.sh
REGISTRY=<账号> ./docker/build.sh

# 只构建不推送，先本机验证
REGISTRY=<账号> ./docker/build.sh --no-push

脚本依次做：校验 jar 存在 → 校验 jar 内确实含前端产物与生产配置 → docker build → docker push。

可覆盖的参数（加在命令前，或写进 docker/.env）
参数默认值说明
REGISTRY（空，必须传）你的 Docker Hub 账号名；自建仓库则填完整前缀，如 harbor.xxx.com/bizlens
IMAGEbizlens-ai镜像名，需与网页端建的仓库名一致
TAGlatest镜像标签，生产建议用版本号或日期
BASE_IMAGEeclipse-temurin:8-jre基础镜像（公共 JDK8 运行环境）。镜像内若没有 git，Dockerfile 会自动安装

不想用脚本时，等价命令：

docker build -f svc/Dockerfile \
  --build-arg BASE_IMAGE=eclipse-temurin:8-jre \
  -t 账号/bizlens-ai:标签 \
  svc

构建上下文是 svc/ 而非仓库根目录，配合 svc/.dockerignore 只把 jar 送进构建过程，避免把源码和几百 MB 的 web/node_modules 传给 Docker daemon。

首次构建会先拉取基础镜像（约 90MB），并在镜像内安装 git（代码索引功能需要）。网络受限时这一步可能很慢或超时，处理见常见问题。

5第三步：推送到私有仓库

# build.sh 已包含推送；单独执行时：
docker push <账号>/bizlens-ai:1.0.0

# 确认本地镜像
docker images | grep bizlens-ai

标签命名建议

  • 每次上线用唯一标签（版本号如 1.0.0，或日期如 20261009），便于回滚；
  • 同时把 latest 指向当前版本，新环境可直接拉；
  • 同名标签重复推送会覆盖仓库里的旧镜像，正在运行的容器不受影响。
# 一个版本打两个标签
docker tag <账号>/bizlens-ai:1.0.0 <账号>/bizlens-ai:latest
docker push <账号>/bizlens-ai:1.0.0
docker push <账号>/bizlens-ai:latest

6第四步：目标机器拉取并启动

6.1 先登录（私有仓库必须）

docker login -u <DockerHub账号>
# Password 填 Access Token

不登录直接拉取会报 unauthorized: authentication required。登录凭证保存在 ~/.docker/config.json，重启机器后一般仍有效。

6.2 准备环境变量

docker/.env 已在 .gitignore 中，不会进仓库。

cp docker/.env.example docker/.env
vi docker/.env
环境变量（必填项缺一个容器即启动失败并明确报出来）
变量必填说明
REGISTRY是你的 Docker Hub 账号名，脚本据此拼镜像名
DATABASE_URL是形如 jdbc:postgresql://主机:5432/bizlens
DATABASE_USERNAME是数据库账号
DATABASE_PASSWORD是数据库口令
REDIS_HOST是Redis 地址
REDIS_PORT是Redis 端口
REDIS_PASSWORD否可为空
AES_KEY建议Git 令牌加解密密钥，32 位以上；不传会退化为源码内置开发密钥
JWT_SECRET建议登录态签发密钥，32 位以上；不传会退化为源码内置开发密钥
AI_EMBEDDING_*否语义召回，不启用则只走关键词召回
BIZLENS_GIT_PROXY否索引克隆仓库的出网代理，默认直连
BIZLENS_GIT_NO_PROXY否不走代理的地址，内网 Git 地址必须写进来，否则会 502
HOST_PORT否宿主机端口，默认 10610
TAG否要拉取的镜像标签，默认 latest

文件格式必须是纯 KEY=VALUE：不要写 export、不要加引号。脚本会先做一次 CR 清理再读取，但格式本身仍按此要求写。

6.3 启动推荐

./docker/run.sh

# 换宿主机端口（10610 被占用时）
HOST_PORT=8080 ./docker/run.sh

脚本会：校验环境变量 → 拉取镜像 → 删除同名旧容器 → 启动新容器 → 轮询健康检查，就绪后打印访问地址。

6.4 手写 docker run

docker run -d \
  --name bizlens-ai \
  --restart unless-stopped \
  -p 10610:10610 \
  --env-file docker/.env \
  <账号>/bizlens-ai:1.0.0

-p 左边是宿主机端口、右边是容器端口。容器内固定监听 10610，一般只改左边；前端所有请求都是同源相对路径，换端口不需要重新打包。要让容器内也换端口，用 -e PARAMS="--server.port=8080"，同时把 -p 右侧改成 8080。

7验证与日常运维

# 1) 服务探针（返回 JSON 即后端就绪）
curl http://127.0.0.1:10610/api/system/health

# 2) 首页（应返回前端 index.html）
curl -I http://127.0.0.1:10610/

# 3) 启动日志（含入口脚本打印的连接目标）
docker logs -f bizlens-ai

# 4) 容器状态与端口映射
docker ps | grep bizlens-ai

浏览器打开 http://<运行机IP>:10610/ 即见登录页，前端页面与后端接口在同一端口下，无需额外前置代理。

启动日志会打印生效的 DATABASE_URL、DATABASE_USER、REDIS（不含口令），便于确认容器连的是不是目标环境。出现「缺少必需的环境变量」说明 docker/.env 有遗漏；出现「未设置 AES_KEY / JWT_SECRET」只是提醒，容器仍会启动。

8版本升级与回滚

应用无状态（会话缓存在 Redis，索引临时目录随容器销毁），升级就是换镜像重启容器。

# 1) 本地重新打包
bash docker/package.sh

# 2) 传到构建机覆盖旧 jar
scp svc/target/bizlens-ai-service-0.0.1-SNAPSHOT.jar <用户>@<构建机>:/data/bizlens/svc/target/

# 3) 构建新版本并推送（换新标签）
cd /data/bizlens && REGISTRY=<账号> TAG=1.0.1 ./docker/build.sh

# 4) 目标机器拉取新版本并重启
TAG=1.0.1 ./docker/run.sh

回滚

把 TAG 换回上一个版本号重新执行 run.sh。旧镜像仍在私有仓库与本地，回滚不需要重新构建。

数据库变更

容器不会自动执行 SQL 迁移。若本次版本涉及表结构变更，需先按 svc/src/main/resources/db/ 下的脚本在目标库手工执行，再启动新容器。新建库用 schema-postgresql.sql；已有库按序号执行 migration-*.sql（可重复执行）。

9常见问题

现象原因与处理
docker login 报 unauthorized: incorrect username or password 用了账号密码登录。Docker Hub 的 CLI 登录必须用 Access Token：网页端 Account Settings → Personal access tokens 生成（权限 Read & Write），登录时粘贴到 Password 位置。
push 报 denied: requested access to the resource is denied 命名空间不对或未登录。REGISTRY 必须是你的 Docker Hub 账号名（要与登录账号一致），不能是 library 或别人的账号。
push 报 repository does not exist or may require 'docker login' 仓库不存在。先在 Docker Hub 网页端创建名为 bizlens-ai 的私有仓库，再推送。
目标机 pull 报 unauthorized: authentication required 私有仓库需先在目标机执行 docker login（用 Token），再拉取。
拉取基础镜像或推送镜像很慢、超时 Docker Hub 网络问题。可给 Docker daemon 配置 registry mirror（/etc/docker/daemon.json），或在能出网的机器上先 docker pull 再 docker tag/save、load 中转。
未找到 bizlens-ai-service-*.jar 本机没打包或没传上去。先本地执行 docker/package.sh，再把 jar 放到构建机的 svc/target/ 下。
提示 jar 内未找到前端产物 / 生产配置 用到的是旧 jar，或打包时前端构建失败。重新执行 docker/package.sh，确认结尾打印出「完成：…jar」。
docker build 报找不到 jar（no such file or directory） 构建上下文是 svc/，jar 必须位于 svc/target/。不要改动 svc/.dockerignore 的排除规则。
容器反复重启，日志报缺少必需的环境变量 docker/.env 少了数据库或 Redis 项，补齐后重跑 run.sh。
容器启动即退出，报 exec format error 或 /bin/sh^M entrypoint.sh 是 CRLF 换行。执行 sed -i 's/\r$//' svc/entrypoint.sh docker/*.sh 后重新构建。
日志报 Could not resolve placeholder 启动命令漏传环境变量。DATABASE_URL、DATABASE_USERNAME、DATABASE_PASSWORD、REDIS_HOST、REDIS_PORT 五项必填。
能打开页面但接口报错、连不上数据库 容器内的 127.0.0.1 是容器自身，不是宿主机。数据库/Redis 地址要填宿主机可达的 IP，不能写 localhost。
索引代码仓库时报 502 或连不上 设了 BIZLENS_GIT_PROXY 却没把内网 Git 地址写进 BIZLENS_GIT_NO_PROXY，内网流量被送去代理了。
端口被占用（Port already in use） 用 HOST_PORT=8080 ./docker/run.sh 换宿主机端口，或先停掉占用该端口的进程/容器。
